# ReLU Benchmark Report

## 基准与结果（ms, 越小越快）

shape: S=1024, K=1024

| kernel | time |
| --- | --- |
| f32 | 0.01459908 |
| f32x4 | 0.00993609 |
| f32_th | 0.01253724 |
| f16 | 0.00726557 |
| f16x2 | 0.00380230 |
| f16x8 | 0.00573850 |
| f16x8pack | 0.00562739 |
| f16_th | 0.00453591 |

shape: S=4096, K=4096

| kernel | time |
| --- | --- |
| f32 | 0.16970038 |
| f32x4 | 0.17066646 |
| f32_th | 0.16997743 |
| f16 | 0.09788179 |
| f16x2 | 0.08670163 |
| f16x8 | 0.08398414 |
| f16x8pack | 0.10620785 |
| f16_th | 0.13099837 |

## 结论与观察

- f16 明显快于 f32，符合带宽受限的直觉，且 half2/向量化有优势。
- f16x2 通常是最稳的最快实现，f16x8 有时更快但不稳定。
- f16x8pack 在大 shape 下更慢，可能与 pack/unpack + 本地数组带来的寄存器/本地内存开销有关。
- f32x4 和 f32 差距很小，说明 float4 向量化在该 kernel 上收益有限，主要受内存带宽限制。
- `torch.relu` 在 f32 上接近自定义 kernel，f16 上略慢于最优实现。
